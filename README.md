# a2a — 文章转有声 MP3，并且**回听确认数字没念错**

> 把一份写好的稿子，变成一个可以边听边查、手机外放也听得清的章节化 MP3，
> 外加一份带时间点的对照稿，最后再让机器把成音听一遍，确认里面的数字一个都没错。

完全免费、纯本地、不需要任何账号或 API key。

---

## 一、它到底解决什么

写稿 → 念稿 → 听稿，中间最容易坏掉的是**数字**。

一份稿子里写着「正文字符从 12276 增到 19807，增加 61%」，念出来以后你没法确认
听众听到的是不是这三个数。念错了、漏了、量级改了，音频里没有任何痕迹。

`a2a` 的做法是：做完音频之后，用本地语音识别把成音**再听一遍**，然后把听回来的
文字跟你预设的「验证键」逐一比对。少一个，程序就报出来。

```
        听稿（你写的）
             │
     ┌───────┴────────┐
     │  合成 edge-tts  │   顺带拿到每个词的时间点
     └───────┬────────┘
             │
     ┌───────┴────────┐
     │  响度 -13 LUFS  │   手机外放听得清，又不爆音
     │  章节 CHAP/CTOC │   播放器里能按节跳转
     └───────┬────────┘
             │
        成片 .mp3 ──────► 带时间点的对照稿 .txt
             │
     ┌───────┴────────┐
     │  回听 faster-  │   听回来的是「61%」还是「六十一」？
     │  whisper       │
     └───────┬────────┘
             │
      验证键命中报告 ────►  41/41 全中，或明确指出少了哪个
```

## 二、三个保证

| 保证 | 怎么做到的 | 实测 |
|---|---|---|
| **数字不会错** | 回听成音，逐个比对验证键；漏掉的先复验再下结论 | 41/41 命中 |
| **手机外放听得清** | ffmpeg 响度链，目标 −13 LUFS、真峰值封顶 | −13.0 LUFS / 真峰值 −1.0 dBFS |
| **想找哪一段都能找** | edge-tts 的词级时间戳 + 脚本对齐 → 每句一个时间点 | 句级时间点 + 可选逐字稿 |

这套流水线跑过一稿真实材料（26.4 分钟、12 章）：

```
[1/6] synthesize      每章 130–520 个词级标记
[3/6] concat          26.4 min of audio, 12 MiB
[5/6] verify          -13.0 LUFS, true peak -1.0 dBFS, flat factor 0.0, chapters 12 → ok
[6/6] listen back     model large-v3 on cuda/float16
                       回听：41/41 个关键数字命中
```

回听那一步用 `large-v3` 跑在 RTX 4070 Ti SUPER 上，26.4 分钟的音频 **3.4 分钟听完**
（约 7.8 倍实时）；同一份稿子用 `small` 在 CPU 上是 3.1 倍实时。

同一份稿子的回听稿里，数字一个不差（`12276`／`19807`／`61%`／`2.49`／`2.72`），
而「硬指标」被听成「应指标」、「独立来源」被听成「不利来源」——这正是为什么
这套工具只验数字。

## 三、三步用起来

### 第 1 步：装好依赖

```bash
pip install edge-tts mutagen          # 必需
pip install faster-whisper             # 可选，不装就没有回听验证

# 有 NVIDIA 显卡的话，装上这两个，回听就能用 GPU（快十几倍）
pip install nvidia-cublas-cu12 nvidia-cudnn-cu12
```

还需要系统里有 `ffmpeg`（`ffmpeg -version` 看得到就行）。

### 第 2 步：写听稿

听稿是纯文字，章节用一行标记开头：

```
@@P0|开场：今天只讲一件事

这一节先给你地图。接下来三段……

@@P1|证据：三个数字

先说是什么。研究者让久坐的人……
```

规则只有三条：

1. `@@编号|标题` 开头的一行是章节标记，**不会被念出来**；
2. 标记之间的正文**一个字不改**地被念出来，所以要写成「念出来好听的样子」，不是「排版好看的样子」；
3. 数字建议写成中文（`一百四十七万户`），工具会把它转成阿拉伯数字去做验证——两件事不冲突。

正文怎么写（表格线性化、缩写三分法、数字写法、元内容剔除），
见 **[references/writing-guide.md](references/writing-guide.md)**（听稿写作指南）——
规则来自两个前身的真实返工记录。

### 第 3 步：跑

```bash
# 合成 + 章节 + 时间点稿
python -m a2a make examples/sample.txt -o out/sample.mp3

# 再加一层：自动挑 25 个关键数字，回听确认
python -m a2a make examples/sample.txt -o out/sample.mp3 --auto-keys 25

# 或者自己指定验证键
python -m a2a make examples/sample.txt -o out/sample.mp3 --keys examples/keys.json
```

同一个输出文件同时只能有一个运行：任务目录（`out/sample_work/`）有锁，
撞上了直接**退出码 5**，不会互相覆盖中间产物。锁是 OS 级的，进程崩了自动释放。

输出四个文件：

| 文件 | 是什么 |
|---|---|
| `out/sample.mp3` | 成品，带章节标记，手机能按节跳转 |
| `out/sample.txt` | 带时间点的对照稿，**每一句**都有时间 |
| `out/sample.words.txt` | 逐字稿（加 `--word-level` 才有），每个词一个时间 |
| `out/sample.heard.txt` | 机器回听到的原文（做了回听验证才有） |

## 四、常用命令

```bash
python -m a2a parse   examples/sample.txt          # 看章节表
python -m a2a audit   examples/sample.txt --source 原稿.md   # 数字对不上原稿就报出来
python -m a2a keys    examples/sample.txt --top 30  # 自动挑验证键
python -m a2a preflight examples/sample.txt keys.json        # 验证键是不是真在稿子里
python -m a2a listen  out/sample.mp3 --keys keys.json        # 只做回听验证
python -m a2a check   out/sample.mp3 --chapters 4    # 只量响度、峰值、章节表
```

## 五、为什么数字可以这么验

中文数字在语音识别里会被**还原成阿拉伯数字**。实测：

| 稿子写的 | 机器听到的 |
|---|---|
| `增加百分之六十一` | `增加61%` |
| `一万二千二百七十六` | `12276` |
| `二零二六年十月` | `2026年10月` |

所以：**稿子用中文数字念（好听），验证键用阿拉伯数字写（可验）**，两件事同时成立。

但**文字**不可靠。同一次回听里，「硬指标」被听成「应指标」，「独立来源」被听成
「不利来源」。所以这套工具只验数字和术语，不做全文逐字比对——这不是偷懒，是
测量结果决定的。

### 漏了一个键 ≠ 音频坏了（自动复验）

识别会把念对的数字听错。所以某个键没命中时，**不做结论，先复验**：用另一套
解码参数（beam=1）只重听这个数字该在的那几秒——句级时间点让窗口精确到句——
然后按两遍读法的关系下结论：

| 复验结果 | 判定 | 你要做什么 |
|---|---|---|
| 第二遍听到了 | 第一次是识别噪声，**音频没问题** | 什么都不用做，算命中 |
| 两遍都没听到，且都读成**同一个别的数** | 音频疑似损坏 | 程序直接给出修复命令（删那一章的 raw 文件 + `--resume`，只重做一章） |
| 两遍都没听到，读法不一致 | 无法判定 | 报告出时间区间，人工复听那几秒 |

单独跑 `listen` 时没有句级时间点，复验退化为整档重听一遍，只能区分前两种的
第一种；剩下的诚实报「无法判定」，不猜。

### 型号里的数字不是数据（自动剔除）

`MI355X` 的 355、`gfx950` 的 950、`H100` 的 100、`Llama-3.3-70B` 的 70——这些
数字确实在稿子里，但它们是型号，不是数据。合成端念型号常变形，回听必然报
「未命中」，而且重做也不会好：是**必然的假警报**。

`--auto-keys` 会先把这类候选剔除再挑键（并打印剔了什么）；`keys` 命令的表格里
用 `⚠ 型号内部` 标出来；`preflight` 对手写的键给同样的警告。判据是：这个数的
**每一个**出现位置都嵌在拉丁 token 内部——只要有一处是独立数字，就当真数据放行。

## 六、模型选多大

默认用 `large-v3`——三个模型里最准的一个，而这套工具验的就是数字。

在本机实测：

| 模型 | 体积 | CPU（int8）速度 | GPU（float16）速度 | 数字准确率 |
|---|---|---|---|---|
| `large-v3`（默认） | 3.0 GB | 0.64 倍实时（比实时慢） | **8.2 倍实时** | 全对 |
| `medium` | 1.5 GB | 约 1.2 倍实时 | 更快 | 全对 |
| `small` | 0.5 GB | 3.1 倍实时 | 更快 | 全对 |

`large-v3` 在 CPU 上比实时还慢：26 分钟的稿子要回听约 40 分钟。**有 NVIDIA 显卡
就不必付这个代价**——补两个 pip 包，程序会自己把 CUDA 库挂上：

```bash
pip install nvidia-cublas-cu12 nvidia-cudnn-cu12
```

装完之后同一份稿子在 RTX 4070 Ti SUPER 上 **8.2 倍实时**，3 分钟跑完。
没有显卡就用 CPU，或加 `--stt-model small` 换快（数字一样全对）。

大模型并没有把**数字**听得更准（三档都全对），它改善的是同音字——而那部分本来
就不验，所以差别只在速度与内存，不在可靠性。

## 七、已知限制

- **回听只验数字**。文字层面的同音字错误不会报错（原因见第五节）。
- **edge-tts 是公共服务**，没有 SLA。程序有重试，但大段文字偶尔会失败，重跑即可
  （加 `--resume` 会接着上次的进度做）。
- **Windows 控制台默认不是 UTF-8**。程序在导入时会把输出流改成 UTF-8，所以
  中文标题不会因为 `cp950` 而崩掉。
- **合成需要联网**（edge-tts）；**回听不需要联网**（模型本地跑，第一次要下载）。
- 一次合成一章，长稿建议拆成多章，这样断线重试只损失一章。
- **默认模型是 `large-v3`（3 GB）**。CPU 上它比实时慢，26 分钟的稿子要回听约
  40 分钟；装上 CUDA 运行库用 GPU 就只要 3 分钟。赶时间用 `--stt-model small`。

## 八、它和另外两个项目的关系

- **`article-to-audio`（v1）**：用平台 TTS/STT，能回听验证，但要桌面常驻、
  烧平台额度。
- **`article-to-audio-2`（v2）**：纯免费，有章节、响度、时间点稿，但**不验内容**。
- **`article-to-audio-3`（本项目）**：v2 的免费 + 章节 + 响度 + **句级时间点**，
  加上 v1 的**回听验证**，全部本地跑，零额度零 key。

具体来说：

- 从 v2 继承：`script`（听稿格式）、`audio`（响度链）、`tags`（ID3v2.4 章节）、
  `verify`（响度测量）、`audit`（数字稽核），**连同那三个已经修好的 bug**。
- 从 v1 移植：`numbers` / `keys` / `match`（中文数字引擎、验证键抽取、三层比对），
  以及 v1 用真实事故换来的三道防护——**漏键复验**（区分识别噪声与音频损坏，
  v1 为此连踩三次坑）、**型号假键剔除**（`preflight-all.mjs` 移植，含 2026-10-23
  的修正：只判前一字符）、**任务目录并发锁**（v1 实测过两个运行互相覆盖校验结果，
  25/25 与 20/25 交错）。锁换成 OS 级（LockFile/flock），进程崩溃自动释放，
  冲突时退出码 5。
- 新写：`synth`（词级时间戳）、`align`（词对回脚本切句）、`stt` + `content`
  （本地回听）、`transcript`（句级时间点稿）、`lock`（workdir 并发锁）。

## 九、代码结构

```
a2a/
  script.py      听稿格式（@@ID|标题）
  numbers.py     中文数字引擎：扫描、解析、还原写法
  keys.py        验证键抽取、排序、预检、数字写法体检
  match.py       三层比对（原文 / 正规化 / 去千分位）
  synth.py       edge-tts 合成，顺带抓词级时间戳
  align.py       词对回脚本 → 句子
  audio.py       ffmpeg 响度链与无损合并
  tags.py        ID3v2.4 CHAP/CTOC 章节表
  transcript.py  带时间点的对照稿
  stt.py         faster-whisper 回听
  content.py     回听 + 比对 + 漏键复验
  verify.py      响度 / 峰值 / 章节表体检
  audit.py       数字与外来词稽核
  lock.py        任务目录并发锁（LockFile / flock，崩溃自动释放）
  pipeline.py    串起来
  __main__.py    命令行
```

跑测试：

```bash
python -m unittest discover -s tests -t .
```
